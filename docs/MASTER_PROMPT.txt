3. USER JOURNEYS (build to these, screen for screen)
Journey A — Feed Test (the hero flow)
1. Farmer opens app → large "TEST FEED" button, spoken prompt in their language
2. Selects feed type from a 3D carousel of photoreal feed models
   (maize silage, wheat straw, cottonseed cake, mustard cake, TMR, green fodder,
    concentrate mix, berseem, napier)
3. App pairs with handheld over BLE (auto-reconnect to last device, 2 s)
4. On-screen 3D animation shows exactly how to fill the sample chamber — the real
   device model rotates and demonstrates. Farmer copies it.
5. Presses scan on device OR in app. LED ring pulses. Progress ring on phone mirrors it.
6. 90 s: device sweeps 900–1700 nm, captures 228 bands x 3 repeats, plus temp/humidity,
   plus a 4-angle macro photo burst for the vision model.
7. Spectra stream to phone over BLE in 512-byte chunks with CRC. Phone runs:
      - SNV + Savitzky-Golay preprocessing
      - PLS/CNN hybrid for CP, moisture, ADF, NDF, ash, ME
      - Classifier head for urea / silica / melamine adulteration
      - MobileNetV3 on the macro images for mould + foreign matter
8. Results render progressively — moisture first (fastest), then the full panel.
9. 3D NUTRIENT VIEW: a volumetric composition model the farmer can rotate; deficient
   fractions glow amber, adulterants pulse red with a callout.
10. Advisory card + voice playback. Three actions: SAVE / COMPARE / SHARE VIA WHATSAPP.
11. Record queues for sync. A small cloud icon shows "saved on phone, will upload".
Journey B — Silage Bunker Monitoring
1. Farmer registers a bunker: photo, dimensions, crop, ensiling date, 3–6 probe positions
2. App builds a 3D digital twin of that bunker at the real dimensions
3. Probes report pH, temperature, moisture, CO2, VOC every 30 min over LoRa/BLE
4. Twin renders a volumetric heat field — cool blue = well fermented, red = aerobic spoilage
5. Farmer can slice the bunker with a drag gesture to see the interior cross-section
6. Forecast model predicts spoilage front propagation 7 days out, shown as an animated
   advancing surface with a countdown: "Feed out from the left face within 5 days"
7. Push/SMS alert on threshold breach, works even on a feature phone via SMS fallback
Journey C — QR Traceability
Feed mill scans a batch → uploads the batch's lab + NIR profile → gets a QR
Farmer scans that QR at purchase → sees the declared profile
Farmer tests the actual bag → app diffs declared vs measured
Mismatch > tolerance → flagged, logged, reported to FPO dashboard, dispute record created

6. 3D UI SPECIFICATION — "REALISTIC, SYNCHRONIZED"

6.1 The rule
No 3D object exists unless it answers a question. Every mesh is bound to a value in the app store. If you delete the data, the mesh must disappear or grey out. Decorative 3D is rejected in code review.

6.6 Binding pattern (write it exactly this way)
// ONE store. The chart, the advisory text, the voice line and the mesh all read from it.
const proximates = useResultStore(s => s.active?.proximates)

// Mesh reacts to data. Data never lives in the mesh.
<NutrientVolume
  fractions={proximates}                 // drives partition heights
  adulterants={result.adulterants}       // drives red inclusion instancing
  confidence={result.confidence}         // drives material roughness/opacity haze
  onFractionTap={id => speak(explain(id))}
/>
If a 3D component holds a useState that duplicates domain data, it is a bug. 3D components take props and emit events. Nothing else.

CI fails if generated files drift from the schema. This is what makes the system "synchronized" in the real sense: one definition, four surfaces, zero drift.

8.4 Sync engine algorithm
on (connectivity OR manual OR every 15 min OR app foreground):
  1. handshake → server returns {server_time, schema_version, model_version, cursor}
  2. if client schema_version < server → block writes, prompt "update app", allow reads
  3. PUSH:  take up to 50 pending records ordered by (priority, captured_at)
           POST /sync/push  with Idempotency-Key = sha256(batch ids)
           server returns per-record {accepted | duplicate | conflict | rejected+reason}
  4. PULL:  GET /sync/pull?cursor=…&limit=200  → apply, advance cursor atomically
  5. RESOLVE: field-level merge for mutable entities; surface true conflicts in Screen 17
  6. MEDIA: separate queue, Wi-Fi/charging only unless user forces, resumable ranges
  7. record sync_run row: started, ended, bytes_up, bytes_down, errors
Backoff: 2s → 4s → 8s → … → 15 min, with jitter. Never drain battery retrying.
Data guard: hard cap of 20 MB/month on cellular by default, configurable, shown to user.

9.2 Data strategy (be honest about this — it's the hardest part)
1. SEED (n≈400): partner with a state veterinary university / KVK. Send paired samples
   to a NABL lab for wet chemistry (AOAC) while scanning with the device. This is ground truth.
2. AUGMENT: spectral augmentation — additive noise, baseline drift, multiplicative scatter,
   wavelength shift ±2 nm, temperature-effect simulation. 20× expansion.
3. SPIKE: deliberately adulterate known-clean samples at 0.5/1/2/4/8 % urea, 2/5/10 % sand,
   to build a labelled adulteration set. Cheap, controlled, high-value.
4. TRANSFER: pretrain on public NIR corpora, fine-tune on the local set.
5. FIELD LOOP: every scan uploads spectrum + (optional) later lab result → active learning
   queue → monthly retrain → signed model bundle pushed to devices over Wi-Fi.
6. CALIBRATION TRANSFER: piecewise direct standardisation (PDS) so a model trained on
   device #1 works on device #500. Each unit ships with a white/dark reference routine
   run before every scan, and a monthly full recalibration prompt.
9.3 Honesty & safety rules in the ML layer
Every prediction returns {value, ci_low, ci_high, confidence, in_distribution: bool}.
If in_distribution == false (Mahalanobis distance beyond threshold), the UI says "This sample looks unlike anything I've been trained on — please send it to a lab" and refuses to print a grade.
No model output is ever used to make a claim about animal safety without the accompanying screening disclaimer and lab-referral path.
Model cards in /docs/model-cards/ state training set size, geography, crop coverage, and known failure modes.
